# 音量の自動補正と保存音声の解析

設定の「音量をそろえる」は既定でオン。「標準」は−16 LUFS、「大きめ」は−14 LUFSを目標とする。YouTube固有の値を取得・追従する機能ではなく、端末内で再生音の大きさをそろえる。スマホの音量設定と元の音声ファイルは変更しない。

## 再生処理

- `LoudnessMeter`: BS.1770のK特性フィルター、400msブロック・100ms間隔の絶対／相対ゲートを使用する。モノラルは二重モノラル相当として扱い、同じ声をステレオで再生したときとの音量差を抑える。保存解析のヒストグラムは0.1 LU刻みで、長時間音声でもメモリー使用量を一定に保つ。認証済み測定器をうたうものではない。
- `LoudnessNormalizer`: 直近最大3秒の測定からゲインを求め、最大増幅は+12dB。上昇は時定数1秒、下降は80msで平滑化し、400msの音が−50 LUFS未満の間はゲインを増やさない。最初の400msは測定を待つ。解析済みの音声では保存値から初期ゲインを決める。
- ピークリミッターは全チャンネルで同じ倍率を使い、最終PCMのサンプルピークを−1dBFSに制限する。アタックは即時、リリースの時定数は100ms。フレーム数・ピッチは変更せず、先読みの遅延は加えない。出力機器や再エンコード後の真のピークまで保証するものではない。
- `NormalizingAudioProcessorChain`: Media3標準の無音・Sonic倍速処理の後ろに補正を置く。Media3の再生時間換算を維持し、倍速後のピークにも上限をかける。
- `NormalizingRenderersFactory`: エンコード音声のパススルーとオフロードを避けてPCMを処理する。端末独自のAudioEffectや追加の外部ライブラリには依存しない。補正をオフにするとPCMはそのまま通す。ソフトウェア処理のため端末によって電池消費が増える可能性がある。

再生項目の判定はアプリ画面の遅れた遷移通知ではなく、Media3の`StreamMetadata`に含まれるタイムライン／periodを使う。シークや次の回への遷移で測定・ゲイン・リミッターをリセットし、別の回の増幅を持ち越さない。オーディオスレッドは設定のスナップショットと解析値のメモリーマップだけを読み、DB・ファイル・通信へアクセスしない。

## 保存音声の事前解析

DownloadManagerの完了通知と、起動・更新時に完了ファイルを確認して`AudioAnalysisJob`を予約する。ジョブはネットワーク不要・バッテリー低下時は待機し、UIを閉じても実行する。1件ずつAndroid標準のMediaExtractor / MediaCodecで最後までデコードする。音声は出力・再圧縮しない。既存の保存済みファイルも対象となる。

解析結果は専用SharedPreferencesに保存し、ファイルのパス・サイズ・更新日時と解析形式の版で照合する。削除・再ダウンロード時は破棄する。解析中にDownloadManagerのIDやファイルが変わった場合は結果を保存しない。失敗や無音の結果も記録して同じファイルを繰り返し解析せず、再生時の補正へフォールバックする。一時的なデコーダー資源不足は後で再試行する。

解析はリポジトリの更新ロックを保持せずに実行し、OSから停止された場合はデコーダーとファイルを解放する。1バッチは約2分を目安に区切り、残りはバックオフ付きで再予約する。1件の解析も2分で打ち切り、処理できない巨大な音声を繰り返し解析しない。1件の解析完了まではバッチの時間枠を超える場合がある。取得状態の全件照会はバッチの開始・終了時に行い、ファイルごとに繰り返さない。設定をオフにすると予約・実行を停止する。

## 検証

既知の1kHz信号でK特性・モノラル／ステレオの整合、無音・背景音のゲート、音量の収束と増幅上限を確認する。Media3の実パイプラインでバッファ境界・倍速・出力ピーク・次の回でのリセットを確認する。保存解析とキャッシュの再利用・無効化、失敗時のフォールバック、設定の保存も回帰テストに含める。端末の出力機器・YouTubeとの聴感の比較と電池消費は、実機で別途確認する。
